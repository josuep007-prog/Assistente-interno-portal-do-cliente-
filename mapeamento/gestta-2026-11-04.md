# Mapeamento do Gestta para a extensão (fase 0)

04/11/2026 · sessão no Chrome do Josué, só leitura · aprovado pelo Josué item a item

## Resumo

O Gestta é viável para a extensão do mesmo jeito que o Onvio: tudo o que as telas mostram vem de uma API JSON em `https://api.gestta.com.br`, autenticada pelo JWT que o próprio Gestta guarda no navegador. Nada exige raspar tela.

Principais achados:

- **Uma chamada traz todas as tarefas do mês numa tabela plana:** `POST /core/customer/task/report` (o motor dos Relatórios) devolve 34 colunas por tarefa, com cliente, CNPJ, regime, setor, responsável, quem concluiu, quando, no prazo, multa e data legal. Em novembro de 2026 foram 8.463 tarefas. É a fonte principal para o Hub.
- **A cartela por setor existe pronta:** `GET /admin/customer/{id}/responsible` diz quem é o analista responsável por cada setor de cada cliente.
- **O painel novo (dashboard-v2) já calcula os alertas** que o escritório quer: gerando multa, atrasadas, pendentes de aprovação, com impedimento, e-mail não enviado, documento do portal não enviado, cobrança de documentos enviada e tarefa que notifica cliente sem usuário de cliente.
- **A fila de envio ao Onvio é legível:** `GET /es/file/onvio` lista cada arquivo que o Gestta tentou publicar no portal, com situação, erro, detalhe e tentativas (ex.: "Pasta de destino não configurada"). É a ponte direta com o cruzamento Onvio × Gestta.
- **Ponto de atenção:** o painel novo e os relatórios leem por **POST** (o filtro vai no corpo). A regra de hoje só libera o POST da busca de tarefas; usar os outros exige autorização nova do Josué (lista em "O que pede autorização").

## Aplicativos e endereços

O Gestta não é um app só. Cada item do menu lateral pode ser outro documento (troca de página inteira), o que importa para a extensão: um script de conteúdo precisa casar com todos.

| App | Endereço | Tecnologia | O que tem |
| --- | --- | --- | --- |
| Clássico | `app.gestta.com.br/#/sidebar/...` | AngularJS 1 | Tarefas (lista e detalhe), Documentos, Relatórios |
| Admin | `app.gestta.com.br/admin/#/sidebar/...` | AngularJS 1 | Clientes, Funcionários, Usuários de cliente, Templates de tarefa e documento, Fluxos, Agrupadores, Feriados, Auditoria |
| Painel novo | `app.gestta.com.br/dashboard-v2/#/...` | React (Vite, React Query) | Dashboard, Lista Detalhada (`#/reports`), Calendário (`#/calendar`), filtros (`#/filters`) |
| Status de integração | `app.gestta.com.br/dominio-integration/#/...` | React | `#/upload` (Domínio) e `#/error-status` (Portal do Cliente) |
| Express | `app.gestta.com.br/express/#/upload` | React | Subir documentos para dar baixa nas tarefas (escrita) |
| Menu lateral | `menu.gestta.com.br` (script) | | Dashboard, Tarefas, Documentos, Relatórios, Apontar, Status Integração, Express, Notificações |

Outros hosts carregados: `gestta.plugsocial.online` (iframe), Intercom, Google Analytics. Nenhum interessa à extensão.

A API usa estes prefixos em `api.gestta.com.br`: `/core/` (tarefas, painel, relatórios), `/admin/` (cadastros), `/es/` (Express e fila de integração), `/nf/` (notificações), `/accounting/` (documentos), `/dominio/` (processos e auditoria do Domínio), `/auth/`.

## Autenticação

- O JWT fica em `localStorage['ngStorage-jwt']`, gravado como texto JSON. `JSON.parse` devolve o valor pronto para o cabeçalho, já com o prefixo `JWT ` (sem `Bearer`). Prefixar de novo dá 401.
- De dentro da página, `XMLHttpRequest` funciona; `fetch` direto para `api.gestta.com.br` falhou nas sessões anteriores com "Failed to fetch". A extensão deve ler de dentro da aba (como no Onvio, mundo da página), com o token só na memória.
- Chaves do `localStorage` (só nomes): `ngStorage-jwt`, `ngStorage-<id da conta>`, `ngStorage-timeRestriction`, `@FilterParams-<id da conta>-<data>`, `@DASHBOARD_WEB`, `@ADMIN_WEB-V2`, `REACT_QUERY_OFFLINE_CACHE`, `gestta-locale`, `i18nextLng`. A extensão não lê nenhuma além do JWT, e o JWT nunca sai da página.
- Sessão expira: a página volta para `app.gestta.com.br/#/login/auth`. A extensão precisa detectar e avisar, nunca tentar logar.

## Tarefas

**Lista** (`#/sidebar/task/overview/dashboard`): filtros na própria URL (`type`, `company_user`, `start_date`, `end_date`, `status`, `date_type`, `no_owner`, `os_workflow`).

`POST /core/customer/task/search` (a única leitura por POST já autorizada)

- Corpo: `page`, `limit` (até 1000), `type[]` (`RECURRENT`, `SERVICE_ORDER`, `ACCOUNTING`), `status[]` (`OPEN`, `IMPEDIMENT`, `DONE`, `IGNORED`, `DISCONSIDERED`; `CANCELED` não existe e dá erro), `start_date`, `end_date`, `date_type` (`DUE_DATE`), `os_workflow`.
- Resposta: `{docs, total, pages, page, limit}`; cada doc com `owner {_id, name, active}` (nulo = sem responsável).
- Janela: um mês por chamada. Doze meses de uma vez deu erro 500.
- Exportação: `POST /core/customer/task/search/export` devolve arquivo (não usar).

**Detalhe** (`#/sidebar/task/overview/dashboard/{id}`):

| Endereço | Formato |
| --- | --- |
| `GET /core/customer/task/{id}` | `type`, `subtype`, `name`, `status`, `overdue`, `fine`, `created_at`, `legal_date`, `due_date`, `competence_date`, `company_task {_id, name, active}`, `company_department {_id, name}`, `customer {_id, name, code, active}`, `customer_has_documents_integration`, `company_documents[]`, `total_step`, `done_step`, `notify_customer`, `notify_whatsapp`, `document_request {active, start, end, notify_email, requested_documents[{name, disconsidered}], billing_format, first_billing_date, recurrence, finalization, send_weekends_holidays}`, `timesheet`, `customer_task_steps[]`, `customer_task_processes[]`, `approvers[]`, `owner {_id, name, active}` |
| `GET /core/customer/task/{id}/history?page&types` | `{docs[{type, status, accomplished_at, comment {external, mentions[], files[]}}], limit, page, totalPages, totalDocs}` (linha do tempo: e-mails de cobrança, comentários, mudanças) |
| `GET /core/customer/task/{id}/collaborator` | `[{_id, name}]` |
| `GET /admin/customer/{id}/accountable?company_department` | usuários de cliente notificados naquele setor: `[{company_department {_id, name}, customer_user {_id, name, email, active, notify_whatsapp}}]` |

Na tela do detalhe há o cronômetro **Apontar**: clicar grava apontamento de horas. A extensão nunca toca nele.

## Painel novo (dashboard-v2)

O próprio app traz o catálogo completo dos endereços, agrupado por método (lido do código do app, `API_URL = {CORE: /core/, ADMIN: /admin/, EXPRESS: /es/, NOTIFICATION: /nf/}`).

**Leitura por GET:** `core/company/department`, `core/dashboard/calendar`, `core/dashboard/calendar/department/{id}`, `core/dashboard/my-filter`, `core/dashboard/attention/{fine,approve,email-not-sent,onvio-documents-not-sent}/all`, `core/company/user/me`, `core/company/workflow`, `core/customer`, `core/company/workflow/{id}/kanban`, `core/customer/workflow/kanban`, `core/customer/workflow/kanban/task/detail`, `core/company/release`; `admin/company/user`, `admin/company/task`, `admin/company/grouper`, `admin/customer/count-without-task`, `admin/company/user/pending-transfer`, `admin/customer/notification/period`, `admin/customer/pending`; `es/file/count-pending` (e `/dominio`, `/onvio`); `nf/notification/count`.

## Relatórios

Tela `#/sidebar/report/list` com relatórios do sistema (Flexmonster): Análise Cliente por Mensalidade, Apontamento Mensal por Cliente e por Usuário, Documentos sem Template Vinculado, Lista e Relação Mensal de Certificados a Vencer, Pontuação Mensal por Cliente e por Usuário, Status Geral de Baixa com Template Vinculado, Status de Baixa por Departamento e Usuário, Status de baixa dos documentos, Tarefas Fechadas com Multa, Tarefas Fechadas em Atraso, Tarefas não Baixadas, Tarefas por Cliente, Colaborador, Departamento, Empresa e Regime, Valor de SS por Cliente. Há ainda relatórios salvos e compartilhados.

- `GET /core/report` e `GET /core/report/{id}`: definição de cada relatório (`name`, `type`, `filter` em texto, `settings` da tabela dinâmica).
- `POST /core/customer/task/report`: os dados. Corpo `{type, filter, dates {startDate, endDate}}`; `type` é uma de `CUSTOMER_TASK`, `CUSTOMER_CERTIFICATE`, `COMPANY_USER_TIMESHEET`, `CUSTOMER_TASK_DOCUMENT`. Resposta em fluxo (cabeçalhos `x-total-records` e `x-estimated-content-length`), lida aos pedaços pelo app.
- Colunas de `CUSTOMER_TASK` (34): `id`, `name`, `type`, `subtype`, `status`, `company_department.name`, `owner.name`, `owner.role`, `notify_customer`, `fine`, `_due_date`, `due_iso_week`, `legal_date`, `downloaded`, `done_overdue`, `done_fine`, `value`, `created_at`, `concluded_by.name`, `concluded_by.role`, `conclusion_date`, `overdue`, `on_time`, `company_task.score`, `company.name`, `company.status`, `company.created_at`, `customer.active`, `customer.cnpj`, `customer.name`, `customer.code`, `customer.federal_regime.name`, `customer.monthly_payment`, `customer.company_groupers`.
- Carga: o mês inteiro levou dezenas de segundos. Na extensão, um mês por chamada e no máximo uma rodada por dia.

## Equipe e usuários de cliente (admin)

- `GET /admin/company/user?active&limit&page&search&sortField&sortType`: funcionários do escritório: `name`, `email`, `role`, `active`, `company_departments[]`, `external_id`, `root`, `temporary_owner`.
- `GET /core/company/user/me`: o usuário logado.
- `GET /admin/company/user/pending-transfer`: inativos com tarefas atreladas.
- `GET /admin/customer/user?active&limit&page&search`: usuários de cliente: `name`, `email`, `active`, `external_id` (preenchido = integrado com o Domínio), `notify_whatsapp`, `customers[]` (nomes). Mais de 2000 usuários; paginar com `limit=200`.
- `GET /admin/customer/user/{id}/accountable`: pares cliente × setor de cada usuário de cliente (o que o setor recebe).
- `GET /admin/company/department`: setores da conta (sistema e customizados, como Contábil1, Fiscal Domínio, Fiscal Conexos).
- Auditoria: `GET /admin/audit?model=customer_user&document_id&limit&page` e `GET /core/dominio/audit` (integração Domínio; `payload.external_id` é o GUID do usuário no Onvio).

## Riscos e limites

- API não oficial e sem documentação: se mudar, a extensão tem de falhar de forma visível, igual ao Onvio.
- Volume: 8 mil tarefas por mês e mais de 2 mil usuários de cliente. Sempre paginado, um mês por vez, uma leitura por vez com pausa.
- Vários apps em páginas diferentes: o script de conteúdo precisa valer para `app.gestta.com.br/*` e saber em qual app está.
- Dados sensíveis que aparecem nas respostas e nunca vão ao armazenamento nem ao Hub: senhas do cliente (aba Senhas), permissões e login dos funcionários, telefone, mensalidade (`monthly_payment`, `value`) até o Josué decidir.
